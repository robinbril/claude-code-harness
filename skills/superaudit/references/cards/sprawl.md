What can **go**, what must become **one**, what needs an **owner**? Ask of every addition: which user-visible capability disappears without it? Classes (put one in `sprawl_class`):
W1 overcomplex: outline the simpler form and why it meets every caller. W2 rivals: two places answer the same question; give an input where they differ. W3 leftovers after a change: zero users, and the hunk that made it obsolete. W4 code for a state that cannot or hardly occurs: the type, constraint or caller that excludes it. W5 generality nobody varies. W6 defensive layers: which error is hidden from whom. W7 wrong or unclear home. W8 compat nobody needs. W9 one rule in several places. W10 tests that only mirror code or keep dead code alive. W11 process residue, text that contradicts the code. W12 new dependency, key, flag, endpoint or table for what exists.
**Search the concept, not the name**: for each new helper, guard, parser, client, list or table, is there already one? Then follow each change backwards: what did it replace, and is all of that gone?
A finding needs all three: you opened it; deleting or merging makes complexity disappear instead of move; the gain is named (`net_lines`, concepts). New or clearly worse than base only.
Keep, however ugly: guards on money, security, personal data, data loss, law or outside input; published contracts and stored data; deliberate duplication with a reason; two codebases that deploy apart; generated code, locale files, flat tables; similar shape with another reason to change.
Fix: delete before merge, merge before move, move before split. Never a new layer, flag, wrapper or generic helper. Severity: high when two versions already answer differently in a common flow or an error is hidden from the user; medium for rivals, dead features, 100 or more lines; low for the rest.
